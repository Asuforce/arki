Architecture

arki は Cloudflare 上で動くブログエンジンです。システムの構成を C4 モデルの 3 つの階層（Context → Container → Component）で示します。

1. System Context2. Container3. Component（API）3. Component（Frontend）投稿・公開の流れ
人arki（対象システム）外部システムコンテナデータストアコンポーネント

Level 1System Context

arki を使う人と、arki がやり取りする外部システム。

Level 2Container

arki を構成する、デプロイされる単位（Worker）とデータストア。

  • ブラウザは ADMIN_TOKEN を持たず、Frontend Worker がサーバー側から API を呼びます。
  • 守りは 2 重です。Access が入口で止め、Frontend Worker も JWT の署名・aud・iss・期限・email を検証します。
  • Import tools は SQL ファイルを作って D1 に流し込みます（実行時の経路ではありません）。

Level 3Component — API Worker

backend/src/ の構成。

Level 3Component — Frontend Worker

frontend/src/ の構成。公開側と管理側でクライアントを分け、公開側にトークンを持たせません。

Dynamic投稿・公開の流れ

  • 読む: ブラウザ → Frontend Worker →（fetch）→ API Worker → D1。Markdown を HTML にして返し、公開ページは共有キャッシュされます。
  • 書く: 管理者 → Cloudflare Access（Google ログイン）→ Frontend Worker が JWT を検証 → ADMIN_TOKEN 付きで API を呼ぶ → D1 に保存。
  • 画像: 管理画面から送信 → API が Images で AVIF に変換 → R2 に保存し、公開 URL を返します。
  • 移行: はてなブログのバックアップ（Markdown）→ tools/import-hatena.ts が SQL を生成 → D1 に投入します。
  • デプロイ: main の CI 成功後、GitHub Actions が D1 マイグレーション → API → Frontend の順に wrangler deploy します。

詳細は docs/architecture.md を参照してください。
